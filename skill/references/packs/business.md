# 域包：business / internal-tool

## 节点候选库

| 编号 | 名称 | 范围 | 适用 |
|---|---|---|---|
| 00 | 治理 | 业务定位 / 边界 / 合规 / 流程规范 | 必有 |
| 10 | 全局与架构 | 部署 / 数据 / 权限 / 集成 / 审计 | 必有 |
| 20 | 客户门户 | 客户可自助的界面 | 有客户端 |
| 30 | 核心业务流程 | 主链路：接单 → 处理 → 交付 | 必有 |
| 40 | 账户与权限 | 登录 / 角色 / 数据权限 | 有账户 |
| 50 | 单证与数据 | 单据 / 材料 / 字段 / 校验 | 有单据 |
| 60 | 规则引擎 | 归类 / 校验 / 风控 / 参数库 | 有规则 |
| 70 | 结算与计费 | 报价 / 账单 / 对账 | 有收费 |
| 80 | 内部操作台 | 员工 / 运营后台 | 有内部端 |
| 90 | 归档 | 已完成 / 废弃 | 必有 |

## 推导

- 从业务流程 / SOP 出发，不按部门拆。
- 一个节点 = 一段能独立验收的流程，或一套独立变化的数据。
- 客户端与内部端是两个面，分别立节点（20 / 80）。
- 合规 / 审计是横切，放 `10`，除非它是独立交付物。

## 示例：B2B 关务系统

```
00 治理 · 10 全局与架构 · 20 客户门户 · 30 接单与通关 ·
40 账户与权限 · 50 单证与申报 · 60 归类 / HS 引擎 ·
70 结算 · 80 内部操作台 · 90 归档
```

## 注意

- 不要按「前端 / 后端」拆。
- 不要把每个报表都做成节点；报表是条目。
- 业务规则变化频繁时，规则库单独成节点，不要散落在各流程里。
